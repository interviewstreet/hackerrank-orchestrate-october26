## 3. Packaging commands

macOS / Linux (from repo root):
```bash
find code -name "__pycache__" -type d -prune -exec rm -rf {} +
zip -r code.zip README.md code -x "*/__pycache__/*" "*/.venv/*" "*/venv/*" "*/node_modules/*" "*/.git/*" "*/.DS_Store"
unzip -l code.zip | grep -Ei "dataset|\.zip|\.env|\.venv" && echo "PROBLEM" || echo "clean"
```
Windows PowerShell:
```powershell
Get-ChildItem code -Recurse -Directory -Filter __pycache__ | Remove-Item -Recurse -Force
Compress-Archive -Path README.md, code -DestinationPath code.zip -Force
```
Keep `code/cache/` out of the zip if it contains request text or OCR text of evidence (`-x "code/cache/*"`); it is regenerated.

## 5. AI-interview prep (30 min, camera on)

You will be asked about approach, decisions, and how you used AI. Be ready to answer, **pointing to files**:

1. **One-minute pitch.** "Deterministic evidence→facts→policy auditor; LLM only classifies request intent; everything else is parsed and rule-checked and fully traceable."
2. **Why not just prompt an LLM per case?** Exact-match scoring, hallucinated IDs, cost, nondeterminism, can't cite evidence precisely. We measured tokens: ~N total.
3. **How do you decide NOT_APPLICABLE?** `request_text` meaning (multilingual, negations), cross-checked with `CLASSIFY_REQUEST` activity; steps `[]`. Example: "stop marketing emails only" is not a deletion.
4. **Identity resolution.** Current + historical emails/hashes/phones from audit log; sha256 hash relation; 100 of 518 requests used an old email; decoys with same names are not linked.
5. **Time-travel rule.** Only facts ≤ `audit_at`; evidence captured later is never used or cited; where inner snapshot timestamps differ from manifest time we use the inner one.
6. **Claims vs evidence.** `reported_status`, `SUCCESS` results and dashboards are claims; example of a case reported COMPLETE that is INCOMPLETE and how we proved it.
7. **Replication drift.** Primary clean but failover/read replica still has the profile → REMAINING_RECORD.
8. **Recreation paths.** Active flows (`data_flow_*`) and restorable backups; why DISABLE/BLOCK come before delete in ordering.
9. **Policy application.** Show the category→rule table; tombstone keeps `user_id` only; audit records retained and verified PRESENT.
10. **Evidence selection.** Which file is cited and why (latest relevant ≤ audit_at); what you validated on samples.
11. **Evaluation.** Metrics, custom cases, failures/improvements; honest limitations (32 samples, no NA in samples).
12. **Generalization / no hardcoding.** Shuffle test, grep for literals, hidden-test robustness review.
13. **Cost.** Calls, tokens, cost per request; cache; `--no-llm` fallback.
14. **How you used AI.** Gemini/Claude for understanding and planning; coding agent for implementation; you reviewed outputs, ran evaluations, and made the key decisions (e.g., deterministic core, NA via text meaning, sort order). Be truthful about what the AI wrote and what you verified.
15. **What you'd do next.** Confidence scoring per finding, richer vision extraction, more rule tests, property-based tests.

**Practice:** run prompt **H4** from `03_Build_Prompts.md` with your coding agent the evening before.

## 6. Last-minute failure modes (and fixes)

| Symptom | Likely cause | Fix |
|---|---|---|
| Output has wrong row count | skipped exceptions per case | wrap per-case in try/except that still emits a row (fallback INCOMPLETE with empty/finding-only steps, and log the error); never drop rows |
| Many COMPLETE cases with empty steps | evidence not linked (email case/format) | check normalization; print linked resources |
| Evidence IDs wrong | choosing earliest/any instead of latest ≤ audit_at | fix selection; compare with sample cites |
| NA count too high or zero | LLM prompt too loose/strict | print NA texts, adjust definition |
| `steps_json` rejected | `NaN`, trailing commas, wrong quoting | use `json.dumps` + `csv.writer`; validator |
| Zip rejected | nested archive or dataset inside | repeat packaging checks |
